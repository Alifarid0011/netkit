# Netkit Implementation Plan

> For agentic workers: implement independently owned packages in parallel, integrate and review the whole program before publication.

**Goal:** Ship a usable Linux networking CLI/dashboard with explanation, packet capture, RouterOS management and explicit Tor routing.
**Architecture:** Standard-library Go command dispatcher and service packages. Linux adapters invoke installed iproute2/tcpdump/nft with typed arguments; no shell. No mandatory Go dependencies.
**Tech Stack:** Go 1.24+, Linux, standard system tools.
**Spec:** docs/superpowers/specs/2026-11-01-netkit-design.md (user approved implementation; added Tor requests below).

## Global Constraints
Linux amd64/arm64. MIT. No mutation of development host's networking. Credentials absent from arguments/logs. Default proxy bind loopback. Bounded operations, context cancellation. JSON stdout is machine-readable. Ship source and installable archives. No unsupported performance or parity claims.

## Review Focus
Untrusted flags/targets must never become shell programs. Secrets must not leak through errors/redirects. Packet capture must stop cleanly and report missing privileges. Proxy streaming/shutdown must function. Partially applied remote writes must never be called atomic.
